### App shell

**You own the structure. No screen gets designed until the user can say where everything lives.**

1. Write the classification line (`references/app-taxonomy.md` §1): surface, app type, loop, with any borrowed type named.
2. List the objects and the areas. Count the levels of "where am I" and give each exactly one home (§4, Levels).
3. Choose the primary navigation pattern and the content arrangement for each screen family (§4). Run the cosplay check (§3).
4. Write the screen inventory: every screen as `family:type`, its ten-second job, its primary action, how it is reached. Apply the depth rule to anything the loop touches.
5. Write the platform block (`references/platforms.md`, "What to state in the plan"). An empty `DEPARTURES` line is normal.
6. Look up what is uncertain, with counts (`references/app-taxonomy.md` §8): how peers handle the levels you found hardest.
7. If two shells are both defensible, run **prototype** on them. Do not argue it.
8. Draw the shell as an ASCII wireframe at the widest and narrowest supported sizes, with one real screen inside each.
9. Hand off to **screen**, starting with the loop's screens.

**Reply:** the classification line, the levels and their homes, the navigation pattern and why, the screen inventory, the platform block, the two wireframes, what was looked up and what it showed, open decisions.
