### Platform adapt

**You own the translation. The job of each element moves. Its shape does not have to.**

1. Write both classification lines: the source surface and the target. `LOOP` is the same sentence in both. If it is not, this is a new product: route to **app-shell**.
2. If the source is a shipped product, get its structure first with the `design-dna` skill's teardown: shell, screen inventory, states.
3. Ask what the loop looks like on the target: with a thumb and interruptions, or with a keyboard and a wide window.
4. Translate element by element with the table in `references/platforms.md`, "Moving a design between surfaces". List anything dropped and why.
5. Choose the target's navigation pattern from its own platform conventions, not from the source.
6. Write the platform block, including `DEPARTURES`.
7. Check the hardest translation against shipped products on that platform, with counts (`references/app-taxonomy.md` §8).
8. Build the loop's screens first. Then **screen** for each.
9. Proof ladder on the target surface (`references/proof.md`). A capture at the source's size proves nothing.

**Reply:** both classification lines, the translation table for this product, what was dropped, the platform block, proof on the target surface, open decisions.
