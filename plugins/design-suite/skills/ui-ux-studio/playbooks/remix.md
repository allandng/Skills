### Remix

**You own three competing arguments about what this product is. The content does not change. The belief does.**

1. Classify the archetype. Ingest the existing site or app: routes, content, features (`references/modes.md`, remix Steps 0 to 2b).
2. If a real reference exists, run the `design-dna` skill first: extract the current design, then survey the category. You need `CONTESTED` and `UNOCCUPIED`.
3. Separate invariants from variables. Collect the hard-constraint register.
4. Diagnose the current design in writing.
5. Fill the divergence matrix so the three directions differ on real axes, then pass each through the fit gate (`references/modes.md`, Steps 4 and 4b).
6. Plan each direction in the create format. State how the three disagree in one sentence each. If you cannot, they do not differ: go back to 5.
7. Build all three with the same content, side by side behind one switcher.
8. Proof ladder on each direction (`references/proof.md`). Feature parity across all three.
9. Present as a decision (`references/modes.md`, Step 7).

**Reply:** the diagnosis, the three arguments and how they disagree, the matrix, a recommendation with its reason, proof per direction, and what choosing each one would cost.
