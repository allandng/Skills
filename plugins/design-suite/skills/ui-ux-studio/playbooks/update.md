### Update

**You own invisibility. The new work must be indistinguishable from what was already there.**

1. Confirm the archetype. Do not reclassify an existing product without saying so.
2. Acquire the system: run the `design-dna` skill's extract on the site or codebase. You need `tokens.json`, the manual pass, and especially `GAPS` and `STATES`.
3. Build the pattern inventory (`references/modes.md`, update Step 2). For an app, name each existing screen as `family:type` (`references/app-taxonomy.md` §5).
4. Find the nearest precedent for every element of the new work. Extend the system only where there is none, and list each extension.
5. If the existing system is bad, stop and give the user the choice in `references/modes.md`, update Step 5. Do not quietly fix it.
6. Build. No new favicon: match the existing title pattern.
7. Verify with a diff: new next to old, same viewport. Then the proof ladder including the parity rung (`references/proof.md`).

**Reply:** what was added and where, the precedent each part follows, every extension to the system and why it was needed, the side-by-side evidence, gaps left in the system.
