### Weekly

**You own a short, honest read of the same numbers, the same way, every week.**

1. The same metrics as last week, from `docs/product/context.md`, computed the same way. Do not add a metric because it looks good this week.
2. Each number against the same week last year where that exists, and against the trailing four-week range. One week against the previous week is mostly noise.
3. Active users as new, retained, resurrected, and the loss as churned.
4. The newest cohort that is old enough, against earlier cohorts at the same age.
5. By platform. On mobile, note any release in the window.
6. Flag only what is outside the usual range. Say "within normal variation" for the rest and move on.
7. For anything flagged: is it real (the `metric-check` skill)? If yes, name the playbook that follows. Do not diagnose in the weekly.
8. Tracking health: the `tracking-plan` skill's event QA and plan comparison on the week's export.
9. Open experiments: days left, split check. Not the metric.

**Reply:** the table with comparisons and ranges, what is outside the range and whether it is real, tracking health, experiments in flight, and at most three follow-ups with owners.
